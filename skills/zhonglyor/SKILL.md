# Жонглёр задач
«Накидываю идеи линейно — ты умеешь взять задачу в план и, не прерываясь, завершить начатое, если оно важно или срочно,
потом взять следующее. Как проект-менеджер, но лучше: ты знаешь специфику своей работы».

## На каждое новое поручение — за 10 секунд
1. **Записать сразу:** `task.py new --title … --check …` (навык `mila-tasks`); идея без срока — туда же с `--kind research`.
   Хозяину — одна строка «Взяла: …».
2. **Решить, когда** — `zhonglyor.py when`:
   - срочно (деньги, человек ждёт, сломано, событие сегодня) → беру сейчас, текущее — паузой с заметкой `task.py note`;
   - текущее почти готово (≤ 3 шагов) → доделываю, потом новое;
   - остальное → в очередь по приоритету (сегодня / неделя).
3. **Решить, как** — самый дешёвый способ, который даст качество (`zhonglyor.py how --kind …`):

   | Задача | Способ |
   |---|---|
   | короткая, моя | сама, сейчас |
   | широкий поиск по файлам или чужому сайту | помощник (Explore) — в мой разговор только вывод |
   | много однотипного (30 чатов, 15 картинок) | параллельно: фоном или workflow, если хозяин разрешил |
   | рутина, сводка, классификация | помощник на лёгкой модели; Jev — для «что это» по правилам |
   | дело другой Милы (контент, видео, сайт, клиент) | записка ей с фактами и границами, проверка «взяла» |
   | деньги, необратимое, от имени хозяина | готовлю и спрашиваю «да» кнопками (навык `iniciativa`) |

4. **Закрыть с уликой:** `task.py done <id> --proof …` и строка «Готово: … (ссылка)».

## Нельзя
- Терять нить: новое поручение без записи в задачи.
- Бросать почти готовое ради нового несрочного.
- Тратить сильную модель на рутину и лёгкую — на текст наружу.
- В спешке говорить факт по памяти: перед фразой о факте — проверка инструментом (урок 28.10: в потоке из 30 голосовых
  дважды прозвучала неправда по памяти).
